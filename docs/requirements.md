# 交点 Careers（jiaodian-careers）

## 软件需求规格说明书

> 版本：V3.1（第 2 轮需求分析，`::req` 模块开发阶段增量更新——新增大厂综合岗位与京沪事业单位加量）
> 输入：用户本轮设想原文（见文末附录）+ 第 1 轮已交付系统现状
> 内容边界：本文档只收录用户侧功能需求、架构选择（用户决策层）与性能等约束；设计内容归 docs/design.md 与 docs/interaction.md。

目标系统：面向人文、社会科学与理工科交叉人才的招聘信息静态网站。
目标运行平台：Web 浏览器（静态托管，部署于 Render）；数据维护在本地 Node.js 环境完成。
主要使用方式：求职者用浏览器浏览、筛选、收藏岗位；内容维护者通过命令行脚本与规范化数据文件增补、核验、构建与部署。

# 1. 文档目的与系统目标

本文档定义交点 Careers 的软件需求。系统既有能力清单（第 1 轮已交付，保持）：

1. 经来源核验的岗位目录，逐条标注核验层级，筛选、排序、分页、URL 复现、本地收藏。
2. 岗位详情溯源展示（核验锚点、来源链接、报名窗口、即将截止标识）。
3. 规范化数据源（`src/data/jobs/` 批次体系）、增补入口 `add:jobs`、审计门禁 `audit:jobs`（离线结构 + 在线回源）。
4. 遗留复核管线 `recheck:legacy`、聚合测试入口 `npm run test`。
5. 实习线索、方向分析、市场观察等静态内容页。
6. 静态导出与 Render 自动部署。

**本轮（第 2 轮）新增目标**：

7. **信息充实**：岗位详情展示的内容太少——当前 188 条记录中 136 条不展示任何条件字段（专业、学历、薪资、职责等全部空白，只显示「条件见来源」）。要求从来源网页进一步提取更多信息：凡来源页面实际载明的条件信息（专业要求、学历、经验、薪资待遇、岗位职责、招聘人数、报名安排、联系方式等）都应提取入库并完整展示。
8. **失效来源刷新**：对显示「已过期」「状态以原文为准」或在线核验失配的记录，重新查找现行有效来源（同一单位同一岗位的新公告、或原公告的现行地址）；经检索确认没有现行来源的记录删除，不留僵尸数据。
9. **信息源与提取流程优化**：优化来源采集与字段提取的工作方式，使「采集 → 提取 → 证据留存 → 审计」的链路更高效、可重复。
10. **信息展示优化**：详情页与列表卡按记录实际拥有的信息完整展示，层级标识清晰，过期/临近截止状态一目了然。
11. **新增岗位来源**：补充事业单位、科研院所、新型研究机构的相关岗位。
12. **大厂综合岗位**（模块开发阶段新增）：补充腾讯、小米、华为、字节跳动等大型科技企业的综合性岗位，覆盖项目经理、产品经理、AI／机器人相关、AI4S（科学智能）、AI 伦理等职能方向。
13. **京沪事业单位加量**（模块开发阶段新增）：在已采集事业单位岗位基础上，进一步增加北京、上海的事业单位招聘岗位。

系统长期目标不变：成为交叉背景求职者可信赖的信息入口——宁可少展示，不可展示未经核验或编造的内容。

# 2. 产品定位

系统定位：招聘信息聚合与核验展示站点，不做简历投递、不代理招聘流程，只提供经核验的信息与原始来源链接。

核心业务对象（在既有 Job、Discipline、JobFunction、报名窗口等概念之上，本轮强调）：

- **岗位（Job）**：条件字段应尽量完整——本轮的填充对象。
- **来源（source_url / source_title / source_evidence）**：每条记录的可复核锚点；来源失效时刷新或删除。

# 3. 用户角色

- **求职者（浏览器访客）**：看到信息完整的岗位详情（专业、学历、待遇、职责、报名安排等），能识别哪些字段经过核验、哪些需以原文为准。
- **内容维护者**：执行来源刷新、字段提取与证据留存；使用增补与审计工具。
- **运行环境参与者**：Render 构建流水线（离线审计门禁）；来源网站（在线审计与提取的访问对象）。

# 4. 总体功能划分

既有功能（保持）：岗位目录与筛选、岗位详情、首页、交叉方向、收藏、实习/分析/市场内容页、核验管线、市场采集、静态部署。

本轮新增/强化：

12. 岗位信息充实（来源页字段提取入库）
13. 失效来源刷新与清理（重新检索 → 刷新或删除）
14. 信息源与提取流程优化
15. 信息展示优化
16. 事业单位、科研院所、新型研究机构岗位补充
17. 大厂综合岗位补充（腾讯、小米、华为、字节等：项目经理、产品经理、AI／机器人、AI4S、AI 伦理）
18. 北京、上海事业单位岗位加量

# 5. 架构选择（用户决策层）

既有决策全部保持：纯静态站点（`output: "export"`）、数据文件化管理、三级核验层级、Render 部署、原页核验锚点强制、推送统一经 `::push`。

本轮新增决策（待用户确认）：

6. **提取辅助脚本化**：字段提取引入辅助脚本（来源页抓取 → 候选字段抽取 → 维护者确认 → 证据留存），辅助脚本不自动写库——写入仍经 `add:jobs`/批次文件 + 审计门禁；核验层级语义不变（提取出的字段必须能回溯到来源页原文，核对不到的留空）。

# 6. 系统运行需求

- 本地运行、构建、审计、测试命令保持不变（`npm run dev/build/test/audit:jobs/add:jobs/recheck:legacy`）。
- 新增提取辅助脚本的运行方式归设计文档。
- 护栏：数据量增长后构建时间与页面加载保持可接受；审计在线模式对慢来源有超时与逐条隔离（不因单条失败中断整批）。

# 7. 岗位目录与筛选（/jobs）——保持，展示强化

既有 10 类筛选、3 种排序、分页、URL 复现不变。本轮强化：列表卡对已提取的条件字段（学历、薪资、经验等）完整展示；「条件见来源」仅用于确实无字段的记录；即将截止与过期状态标识准确（当前存在 1 条截止已过仍标「招聘中」的记录，须随复核清理）。

# 8. 岗位详情（/jobs/[id]）——保持，信息充实

既有结构不变。本轮强化：详情页按记录拥有的字段完整展示原公告信息（专业要求、学历、经验、薪资、职责、招聘人数、报名安排、联系方式等）；各字段的信息范围提示保持（核验层级决定展示口径）。

# 9. 岗位信息充实（本轮新增）

- 用户可见行为：逐字段核验记录展示来源页载明的完整条件信息；来源/关键字段级记录经刷新提取后升级层级并补齐字段；详情页不再出现大面积空白。
- 数据内容：字段值全部来自来源页原文并留存证据片段；提取不到的字段留空；禁止按机构类型或常见待遇推测补写。
- 边界：充实工作优先覆盖当前展示空白的前台记录（现状 136 条），按单位类型与有效性分批推进。

# 10. 失效来源刷新与清理（本轮新增）

- 用户可见行为：前台不出现「该信息已过期」类失效来源记录与截止已过仍标「招聘中」的僵尸记录。
- 处置规则：对失效/失配记录先重新检索现行来源（单位官网、政府人事部门网站的现行公告）；检索到即刷新记录（更新来源与证据，层级按新证据定）；确认无现行来源的删除。
- 边界：检索以可访问的在线来源为准；无法访问来源页的记录不得凭记忆补写后上架。

# 11. 信息源与提取流程优化（本轮新增）

- 维护者视角：存在一条可重复的「采集 → 提取 → 确认 → 入库 → 审计」工作流；提取辅助脚本产出候选字段与证据位置，人工确认后入库；流程对后续持续运营可复用。
- 来源优先级保持：单位官网/官方招聘系统 > 政府人事部门网站 > 转载（转载须注明）。

# 12. 信息展示优化（本轮新增）

- 用户可见行为：详情页信息分区清晰（条件信息、报名安排、来源核验），列表卡信息密度提升且层级标识醒目；移动端体验良好。
- 边界：不改变既有交互逻辑与数据语义。

# 13. 事业单位、科研院所、新型研究机构岗位补充（本轮新增）

- 数据内容：新增这三类单位的招聘岗位；事业单位继续要求报名起止时间（原文有则必录）；新型研究机构（如上海人工智能实验室一类的新型研发组织）与科研院所岗位覆盖科研、工程、交叉职能。
- 数量目标（用户已批准）：三类合计新增不少于 20 条经核验记录，其中事业单位不少于 8 条。
- 地域范围（用户已批准）：延续北京、上海重点并兼顾全国。
- 大厂综合岗位（模块开发阶段新增，数量为建议值待确认）：腾讯、小米、华为、字节跳动等大厂综合岗位不少于 12 条，项目经理、产品经理、AI／机器人、AI4S、AI 伦理五类职能尽量各有覆盖；来源以企业官网招聘系统或官方发布渠道为准（转载须注明）。
- 京沪事业单位加量（模块开发阶段新增，数量为建议值待确认）：北京、上海事业单位在既有基础上新增不少于 6 条（累计事业单位不少于 15 条）。

# 14. 性能需求

- 用户未提出量化指标。现状约束：静态导出、客户端内存筛选、构建期逐岗位生成详情页；数据量增长后构建不失败、页面加载可接受。

# 15. 可扩展性、可维护性与可测试性需求

- 数据充实与来源刷新按批次文件组织，处置留痕（批次头注释），经审计门禁生效。
- 提取辅助脚本可复用于后续轮次的持续运营。
- 测试：模块测试与库级回归按既有体系（docs/test.md 注册表）扩展。

# 16. 验收目标

1. `npm run audit:jobs` 在线模式通过，全部前台记录证据回源命中；`npm run build` 成功且详情页数量与目录一致。
2. 前台无失效来源记录：无「该信息已过期」类来源、无截止已过仍标「招聘中」的记录；失效记录的刷新或删除有处置留痕。
3. 信息充实后：展示空白的记录数量显著下降（现状 136 条），至少 60 条来源/关键字段级记录完成字段提取并升级层级或补齐字段；全部新填字段带证据且可回溯来源原文。
4. 详情页与列表卡按实际字段完整展示；各核验层级的展示口径如实。
5. 新增事业单位、科研院所、新型研究机构岗位合计不少于 20 条（事业单位不少于 8 条），事业单位含报名安排；地域以北京、上海为重点兼顾全国。
8. 新增大厂综合岗位不少于 12 条（腾讯、小米、华为、字节等，覆盖项目经理、产品经理、AI／机器人、AI4S、AI 伦理职能），全部带来源证据。
9. 北京、上海事业单位在既有基础上新增不少于 6 条（累计事业单位不少于 15 条），含报名安排。
6. 提取辅助流程可用且留痕，后续轮次可复用。
7. 既有交互与页面不回归（::lint 与 ::ci 全量通过）。
