# 交点 Careers（jiaodian-careers）

## 用户交互设计说明书

> 版本：V2.0（第 1 轮需求分析 ::design 生成，覆盖 V1 探索版）
> 交互方式：求职者侧为 Web GUI（静态站点，浏览器访客直接操作页面）；维护者侧为 npm 脚本命令行（新增 add:jobs、recheck:legacy）。

# 1. 文档定位与边界

本文档只回答四类问题：①用户与外部系统能与系统发生哪些交互；②每个交互的预期输入是什么、系统如何校验；③预期输出是什么、以什么形式呈现；④输入非法或对端失败时，交互双方各自看到什么。不写需求罗列（归 docs/requirements.md），不写模块划分与模块内部设计（归 docs/design.md 与 docs/modules/）。

# 2. 交互面总览

| 通道 | 形态 | 承载内容 | 协议约定 |
| --- | --- | --- | --- |
| Web 页面（求职者） | 静态 HTML + React 水合 | 岗位浏览、筛选、收藏、内容页 | URL 参数协议（§3）、localStorage 键（§3） |
| npm 脚本（维护者） | 命令行 | 数据核验、增补录入、遗留复核、市场采集、构建部署 | 退出码与控制台输出（§11） |

使用者等价关系：求职者只能经 Web 页面交互；维护者只能经命令行交互；两类使用者无重叠操作。

入口清单：

- Web 页面：`/`、`/jobs`、`/jobs/[id]`、`/directions`、`/favorites`、`/internships`、`/analysis`、`/market`、`/market/robotics`、`/404`。
- npm 脚本：`dev`、`build`、`start`、`audit:jobs [--offline]`、`add:jobs <json> --batch <名称>`（★ 新增）、`recheck:legacy [--offline] [--ids …] [--limit N]`（★ 新增）、`collect:robotics [--offline]`、`test`（★ 新增，聚合测试入口）。
- 已移除：`update.sh`（原直接 git push 的遗留脚本，推送统一经命令系统 ::push）。

# 3. 全局交互协议

- **URL 参数协议**（/jobs 页）：`q`（关键词）、`region`（地区）、`city`（城市）、`org_type`（单位类型）、`job_type`（岗位类型）、`education`（学历）、`discipline`（主学科）、`secondary_discipline`（第二学科/技能）、`function`（★ 新增：岗位职能，取职能枚举值）、`status`（招聘状态）、`sort`（newest/verified/deadline，缺省 newest）、`page`（页码，缺省 1）。筛选变化经 `router.replace` 同步到 URL（`scroll: false`）；空值与缺省值不写入。
- **收藏存储协议**：localStorage 键 `jiaodian-favorites`，JSON 数字数组；解析失败按空数组处理。
- **核验徽标色彩协议**（★ 统一）：逐字段核验=绿、来源核验=蓝、关键字段核验=琥珀、待核实=黄；「即将截止」标识=红色强调。全站一致。
- **错误呈现形态**：静态站点无网络失败场景；非法详情 ID 渲染 404 页；筛选无结果渲染空态文案。
- **外链行为**：全部来源链接 `target="_blank" rel="noopener noreferrer"`。
- **通用行为**：无登录、无服务器表单、收藏为幂等切换。
- **模块间交互线**：本项目模块间全部为进程内直接调用（docs/design.md §4 契约 9），不存在 HTTP、WebSocket、消息队列等模块间交互线，故本文档不设「模块间交互线协议」章；进程内的字段级接口契约归各模块 `docs/modules/{模块}_interaction.md`。

# 4. 全局框架（Header / Footer）

- Header：品牌「交点 Careers」回首页；导航 6 链接——探索岗位(/jobs)、方向分析(/analysis)、市场观察(/market)、实习岗位(/internships)、交叉方向(/directions)、收藏(/favorites)。移动端横向滚动。
- Footer：标语与来源声明。无交互。

# 8. 交叉方向页（/directions）与收藏页（/favorites）

- 交叉方向：11 张方向卡（主×次学科、典型岗位、关键词、计数或「暂无岗位」）；点击跳转 `/jobs?discipline={方向名}`。
- 收藏页：读 localStorage 反查岗位；空态文案；非空渲染 JobCard。localStorage 含已下架 ID 时静默跳过。

# 9. 实习岗位页（/internships）

- 顶部 7 张方向导航卡（计数、锚点）；正文按方向分组渲染线索卡（标题、单位、地点、待遇、学历、批次、摘要、来源外链）；顶部固定「实习岗位正在逐条回源复核」说明条。
- 本轮清理后：失效线索移除，各方向计数如实更新。

# 10. 方向分析页（/analysis）与市场页（/market、/market/robotics）

- 方向分析：7 方向锚点按钮；逐方向详述（聚焦、典型岗位、核心技能、作品集、信号、适配）；背景路线卡；机会样本分节（实习/博士后/企业岗位）带来源外链。无输入控件。
- 市场观察：人才报告摘要、平台渠道说明、机器人专题入口。无输入控件。
- 机器人样本专题：统计概览、方向份额条形、饼图（SVG）、方向薪资中位数表、城市/单位分布、岗位明细表、JSON/CSV 下载链接。无输入控件。

# 11. 维护者命令行交互规格

| 命令 | 输入 | 成功输出 | 失败表现 |
| --- | --- | --- | --- |
| `npm run audit:jobs` | 无参数 | `Audited {N} public jobs ({x} field-level, {y} source-level, {z} key-field) against source pages.` | 逐条错误行到 stderr，退出码 1 |
| `npm run audit:jobs:offline` | 无参数 | 同上，结尾 `(schema only)`，不发网络请求 | 同上（仅结构类错误） |
| `npm run add:jobs -- <json路径> --batch <批次名>`（★ 新增） | JSON 文件（记录数组）+ 批次名（kebab-case） | 逐条写入结果 + `Added {N} jobs to {批次文件}` + 自动执行的 offline 审计计数 | 校验失败逐条列出原因（缺证据字段、日期格式非法、职能/枚举非法等）并拒绝整批写入，退出码 1；批次名非法拒绝 |
| `npm run recheck:legacy -- [--offline] [--ids id1,id2] [--limit N]`（★ 新增） | 可选过滤参数 | 分类统计 + 报告路径 `workspace/legacy-recheck/report.md`；逐条标注可升级/需人工复核/建议下架 | 网络异常逐条记为「需人工复核（访问失败：原因）」，不中断整批；离线模式全量标「未核验」 |
| `npm run collect:robotics [--offline]` | 无参数 | `Generated {N} jobs from {M} public source URLs.` + 来源检查 + 输出路径 | 脚本异常退出码 1 |
| `npm run test`（★ 新增） | 无参数 | 聚合运行 `scripts/tests/` 全部断言脚本，输出各套件通过/失败 | 任一断言失败退出码 1 并列出失败断言 |
| `npm run build` | 无参数 | 构建成功，产物 `out/` | prebuild 审计失败时构建中止 |
| `npm run dev` | 无参数 | http://localhost:3000 | — |

错误分类（audit:jobs，保持并在本轮扩展）：重复 ID、缺 verification_level、缺 source_title/source_evidence、待核实记录携带条件字段、逐字段核验非 HTTPS、含 demo 数据、来源 HTTP 非 200、来源标题/发布日期/证据片段未命中、fetch 异常、★ 报名窗口字段非法（application_opens_at/deadline 非 YYYY-MM-DD 或 opens 晚于 deadline）、★ job_functions 含枚举外值——全部行式输出。

# 12. 端到端交互序列

求职者路径：首页输入关键词+选地区 → 搜索 → /jobs 带参筛选 →（★ 可经职能入口直达「产品经理」等岗位）→ 调整筛选/排序/翻页 → 详情页核对核验层级、报名窗口与原页锚点 → 前往来源确认 → 收藏 → /favorites 复查。

维护者路径（★ 规范化后）：采集来源页并整理 JSON（含证据字段）→ `npm run add:jobs`（校验+自动 ID+写入批次+offline 审计）→ 本地提交 → `npm run audit:jobs`（在线回源）→ `::push` 推送 → Render 自动构建 → 站点更新。

清理路径（★）：`npm run recheck:legacy` → 阅读报告 → 确认处置 → 存活记录经 add:jobs 迁入、失效记录随遗留文件移除 → `npm run audit:jobs` 确认 → 提交。

# 13. 交互验收口径

1. /jobs 页 10 类筛选控件（含岗位职能）均生效且与 URL 参数一一对应；带参 URL 可复现筛选状态。
2. 排序三选项行为：newest 按 published_at 降序、verified 按 last_verified 降序、deadline 按 deadline 升序（null 殿后）。
3. 详情页按核验层级渲染提示条；「待核实」记录无任何条件字段区块。
4. deadline ≤7 天且「招聘中」的岗位在列表卡片与详情页均出现「即将截止」标识；其余情形不出现。
5. 事业单位公告级记录详情页展示报名窗口；原文无时间信息时不显示编造的时间。
6. 收藏切换后刷新状态保持；列表与详情共享同一存储键。
7. 全部来源外链新标签页打开且带 rel="noopener noreferrer"。
8. `audit:jobs`（在线）通过输出各层级计数；任一证据未命中退出码 1。
9. `add:jobs` 对缺证据、日期非法、枚举非法的记录整批拒绝且不产生半写入；合法批次写入后 offline 审计自动执行。
10. `recheck:legacy` 产出 report.md 与 JSON 明细；网络失败不中断整批。
11. `npm run test` 聚合全部断言脚本并以退出码反映结果。
12. 不存在的详情 ID 返回 404 页。
