# data-acquisition 模块设计文档（第 2 轮执行；第 4 轮综合平台扩充）

> 全局契约引用 docs/design.md §4（契约 2、3、5、11、12、14）、§5；本模块为第 2 轮三类单位岗位补充的执行单元（第 1 轮的京沪与跨学科批次已交付，本节按第 2 轮目标重写）。第 2 轮模块开发阶段另承接用户点名的腾讯与华为补采单元（本节一并覆盖）。第 4 轮为用户指定的综合平台扩充执行单元：从综合性招聘平台与官方渠道采集哲学、出版、研究机构与事业单位岗位（详见 §1a、§3a）。

# 1. 模块职责与边界

- 职责：采集并录入事业单位、科研院所、新型研究机构岗位 ≥20 条（事业单位 ≥8 条，含报名安排），地域北京、上海重点兼顾全国；以及第 2 轮模块开发阶段新增的大厂综合岗位 ≥12 条与京沪事业单位增补 ≥6 条；第 2 轮补采单元另需补录腾讯岗位 ≥3 条与华为岗位 ≥3 条（合计 ≥6 条，职能优先 AI 伦理／治理／合规／安全类），每条必须真实访问来源页并逐字段核验后录入。
- 数据所有权：本轮新建批次文件 `src/data/jobs/public-sector-2026-11.ts`（事业单位）、`src/data/jobs/research-institutes-2026-11.ts`（科研院所与新型研究机构，两类合并为一个批次，文件头注明构成）；第 2 轮第二批增量新建 `src/data/jobs/enterprise-bigtech-2026-11.ts`（大厂综合岗位）、`src/data/jobs/public-sector-bjsh-2026-11.ts`（北京、上海事业单位增补）；补采单元新建 `src/data/jobs/tencent-huawei-2026-11.ts`（腾讯与华为岗位补采）。

# 1a. 第 4 轮职责（综合平台扩充）

- 职责：从综合性招聘平台与官方渠道采集并录入哲学、出版、研究机构与事业单位岗位合计 ≥20 条（宁缺毋滥），目标构成：综合性平台（国聘网、央企国企官网等）≥6 条、哲学相关岗位（高校哲学院系教职与科研岗、研究院所哲学与科技哲学方向、科技伦理治理岗）≥4 条、出版相关岗位（出版社、出版集团、学术期刊的编辑／策划／审校岗）≥4 条、研究机构新出岗位 ≥3 条、事业单位（京沪苏杭人社局与事业单位官网现行公开招聘公告）≥3 条。
- 地域与时效约束：城市以北京、上海、苏州、杭州为主（苏州记录 province 为江苏、杭州记录 province 为浙江）；只录报名未截止的公告（deadline 为空且原文注明「长期有效／招满为止」的也可录入，原文写进 application_info）。
- 详细性约束（用户特别要求「每个岗位的招聘信息尽量写详细一些」）：「详细」的前提是「可核验」——每个条件字段（专业要求、学历、经验、薪资待遇、职责、招聘人数、报名起止时间、报名方式、联系方式）都从来源页原文提取并附可逐字命中的证据片段（逐字段核验 ≥3 段）；原文未载明的字段留空，禁止按机构类型或常见待遇推测补写。
- 数据所有权：新建批次文件 `src/data/jobs/comprehensive-2026-11.ts`（文件头注明来源构成）；采集底稿 `workspace/acquisition/sources-4.md`（来源、URL、访问结果、截止与否、放弃原因）。
- 不负责：修改既有批次（data-refresh 所有）、管线脚本（source-tools）、页面代码（jobs-catalog）、批次并入 index.ts（合并阶段由主 Agent 执行）。

# 3. 内部数据流

采集 → 核对 → 录入三步固定顺序（与第 1 轮一致，新增 extract:fields 辅助）：

1. **采集**：来源清单优先级——事业单位：北京市/上海市人社局、区人社局、各事业单位官网的现行公开招聘公告；科研院所：中科院各研究所、社科院系统、部委研究院所官网；新型研究机构：上海人工智能实验室、之江实验室、鹏城实验室、北京智源研究院等新型研发组织的官网招聘页；大厂综合岗位：字节跳动、小米、阿里巴巴、百度、京东、京东方、荣耀、网易、美团、中兴通讯、腾讯音乐等企业官网招聘系统或官方发布渠道（腾讯与华为的候选岗位因反爬拦截或招聘已结束未能核验，见 interaction 文档偏差说明），覆盖项目经理、产品经理、AI／机器人、AI4S 职能。只采集截至采集日现行有效的公告与职位。
2. **核对**：按目标层级准备证据——「逐字段核验」≥3 段原文片段 + 来源页标题 + 发布日期；事业单位公告必须提取报名起止时间（application_opens_at / deadline，原文有则必录）与报名方式（application_info）。
3. **录入**：`extract:fields --scan` 辅助抽取候选 → 人工确认 → 批次文件写入（或 add:jobs）；id 从 3001 起手工段（第二批增量批次从 3101 起）；fetched_at/last_verified = 采集当日。

失败点：来源页无法访问 → 放弃该条并记录原因；内容与预期不符 → 放弃；禁止按机构类型或常见待遇推测补写。官方渠道不可核验而转载页可逐字段核验时，改用转载来源录入（source_type 用「其他」、source_name 注明「转载」），官方原始出处访问失败的原因记入 workspace/acquisition/ 底稿；不因此降低证据要求（仍须 ≥3 段逐字命中）。

补采单元（腾讯与华为）渠道实测结论（第 2 轮补采）：腾讯招聘官网职位详情页（careers.tencent.com/jobdesc.html）为 JS 渲染壳，静态抓取无岗位内容，改用同一官网域名下的职位数据接口（tencentcareer/api/post/ByPostId，返回官方职位 JSON 数据，含职位名称、职责、要求与最近更新时间，逐字段核验）；华为招聘官网（career.huawei.com）职位页为 JS 渲染，改用南开大学学生就业信息网转载的华为校园招聘职位页（静态可核验）；微信公众号文章页（mp.weixin.qq.com）静态抓取仅得分享壳（正文位于脚本变量中，可见文本不足三段证据），公众号渠道整体放弃。腾讯官网以「伦理」「AI治理」检索无结果、华为侧无可核验的 AI 伦理／安全类岗位，均如实放弃并记入 workspace/acquisition/sources-3.md。

# 3a. 第 4 轮数据流补充（综合平台扩充）

第 4 轮沿用采集 → 核对 → 录入三步固定顺序，并按工具链实测约束调整渠道：

1. **渠道约束（工具链限制，实测确认）**：qgsydw.com／zgsydw.com 为 GBK 编码站点，无法在线核验，不作为来源；BOSS直聘／猎聘／飞书招聘详情页为 JS 渲染壳，不作为来源；国聘网（iguopin.com）职位详情页多为 JS 渲染，无法静态核验时改用其官方渠道的静态转载页（如高校就业信息网转载），仍不可核验则放弃并记入 workspace/acquisition/sources-4.md——宁缺毋滥。
2. **来源清单先行**：先建 workspace/acquisition/sources-4.md（来源、URL、访问结果、截止与否），逐个访问；来源页无法访问、内容与预期不符、报名已截止的候选一律放弃并记录原因。
3. **时效过滤**：只录报名未截止的公告——deadline ≥ 采集日（2026-11-11），或 deadline 为空且 application_info 载明报名时效原文（「长期有效／招满为止／招到即止」类，或「报名起止时间未载明」类说明）；「详细」以「可核验」为前提，原文未载明的字段（专业、学历、经验、薪资等）留空，不按机构类型推测补写。
4. **分类标注**：哲学相关岗位 platform_disciplines 用「哲学×社会科学」；出版相关岗位 platform_disciplines 用「人文社科×学术出版」且 job_functions 含「编辑出版」；全部记录 job_functions 按 JOB_FUNCTIONS 枚举标注。
5. **录入与核对**：id 从 3301 起手工段；fetched_at/last_verified = 2026-11-11；每条记录录入前用与 audit-verified-jobs.ts 同口径的规范化回源核对（一次性底稿脚本，提交前删除），source_title、published_at 与全部证据片段须逐字命中。

批次文件记录遵循 `Job` 类型（含扩展字段）；类型别名 `JobWithWindow` 保留（与既有采集批次一致）。
