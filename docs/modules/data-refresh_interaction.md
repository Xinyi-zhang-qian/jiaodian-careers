# data-refresh 模块交互文档

> 本模块无独立命令行入口（使用 source-tools 的命令）；本模块产出为批次文件修改与处置留痕。规格要点：

# 1. 交互面总览

- 输入：`refresh:sources` 分类报告（workspace/source-refresh/）、`extract:fields --scan` 候选（workspace/extract/）。
- 输出：批次文件修改（充实/刷新/删除/状态修正）+ 批次头处置注释；处置执行中 `--apply` 自动触发的离线审计结果。

# 2. 处置规格

- 充实（A 类）：每条记录的每个新填字段必须附证据片段且在线复核命中；层级升级方向只允许 关键字段核验→来源核验→逐字段核验；「逐字段核验」要求全部已填字段证据齐全（≥3 段证据片段）；核对不到的字段留空。目标 ≥60 条。
- 刷新（B 类）：重新检索到的现行来源须实际访问并留存新证据（source_title、≥2 段证据片段）；检索判定以可访问的在线页面为准，检索不到（来源搜索无现行公告）才允许删除。
- 删除（B 类）：批次头注释逐条记录 id、岗位、单位、失效原因、日期。
- 状态修正（C 类）：截止已过且原文确认招聘期结束 → status「已截止」；原文无法确认 → 随 B 类处置。

# 3. 处置验收断言

1. 处置后 `npm run audit:jobs`（在线）全量通过。
2. 前台无「来源过期」分类记录残留；无截止已过仍标「招聘中」的记录。
3. 充实记录 ≥60 条且每条新填字段带证据；充实记录的层级只升不降。
4. 全部删除/刷新有批次头处置注释（id、原因、日期可追溯）。
5. `npm run test` 全部套件通过（数据测试期望随处置同步更新）。
