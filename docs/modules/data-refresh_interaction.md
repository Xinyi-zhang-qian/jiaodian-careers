# data-refresh 模块交互文档

> 本模块无独立命令行入口（使用 source-tools 的命令）；本模块产出为批次文件修改与处置留痕。规格要点：

# 1. 交互面总览

- 输入：全量在线分类结果（第 2 轮以一次性脚本 `scripts/tmp-classify.ts` 产出，落 workspace/source-refresh/；source-tools 的 `refresh:sources` 分类报告合并后格式一致）、失效记录重新检索候选（`scripts/tmp-research.ts` / `tmp-fetch-full.ts` 产出）。
- 输出：批次文件修改（充实/刷新/删除/状态修正）+ 批次头处置注释；处置后 offline 与在线审计结果。
- 本模块无独立命令行入口；source-tools 命令在本模块 worktree 内由等价一次性脚本替代执行（见设计文档 §1 执行路径说明）。

# 2. 处置规格

- 充实（A 类）：每条记录的每个新填字段必须附证据片段且在线复核命中；层级升级方向只允许 关键字段核验→来源核验→逐字段核验；「逐字段核验」要求全部已填字段证据齐全（≥3 段证据片段）；核对不到的字段留空。第 2 轮实际充实 107 条（目标 ≥60 达成）。
- 刷新（B 类）：重新检索到的现行来源须实际访问并留存新证据（source_title、≥2 段证据片段）；检索判定以可访问的在线页面为准，检索不到（来源搜索无现行公告）才允许删除。同 URL 页面存在但锚点失配的记录优先「同源换锚点」刷新（更新 source_title/source_evidence 为现行页面可命中片段）；GBK 编码来源与 JS 渲染壳来源的记录层级不得高于「关键字段核验」（在线审计无法核验其证据）。
- 删除（B 类）：批次头注释逐条记录 id、岗位、单位、失效原因、日期。第 2 轮删除 19 条（JS 渲染壳/404/反爬且重新检索无现行可核验来源）。
- 状态修正（C 类）：截止已过且原文确认招聘期结束 → status「已截止」；原文无法确认 → 随 B 类处置。第 2 轮改「已截止」29 条（含 2016 同济口腔医院）。

# 3. 处置验收断言

1. 处置后 `npm run audit:jobs`（在线）全量通过。——第 2 轮已达成（169 条，0 失败）。
2. 前台无「来源过期」分类记录残留；无截止已过仍标「招聘中」的记录。——第 2 轮已达成（失配 81 条全部刷新或删除；状态矛盾清零）。
3. 充实记录 ≥60 条且每条新填字段带证据；充实记录的层级只升不降。——第 2 轮已达成（107 条，均在原层级上升级或保持）。
4. 全部删除/刷新有批次头处置注释（id、原因、日期可追溯）。——第 2 轮已达成（四个批次文件头）。
5. `npm run test` 全部套件通过（数据测试期望随处置同步更新）。——见 docs/test.md「最近一轮结果」。
