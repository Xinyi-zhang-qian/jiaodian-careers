# ::work -experiment 模板（实验与数据分析）

> 本文件为 `::work -experiment` 的完整协议：「主 Agent 编排」节由主 Agent 执行；「Experiment 子 Agent 协议」节由子 Agent 遵循。
> 由 `system/commands/work.md` 模板分派进入；写作规范与语言风格遵循 `AGENTS.md`。

---

## 主 Agent 编排

`::work -experiment [@<文件或目录路径> ...] <custom prompt>`

围绕用户提出的研究问题，设计并执行实验或数据分析，产出标准化工作目录与固定五章结构的中文最终报告。适用对象：算法对比实验、参数影响分析、数据分析与出图、基准测试等需要「设计 → 执行 → 出图 → 报告」完整链条的任务。

**参数**：

- `<custom prompt>`：**必填**。研究问题与实验要求原文（研究目的、对比对象、关键参数、数据来源等）。缺失时报错中止。
- `@targets`：可选，可重复。种子材料（已有数据文件、相关代码、参考文档等仓库相对路径），解析后注入子 Agent。

**执行步骤**：

1. **解析与校验**：解析 prompt 与 `@targets`；prompt 缺失 → 报错中止；逐一确认 `@` 路径存在，无效目标向用户报告。
2. **建立工作目录**：从 prompt 提炼中文简洁标题（不超过 15 字，去除文件系统非法字符 `/ \ : * ? " < > |` 与空格），确定 `REPORT_DIR = workspace/workreport_{YYYY-MM-DD-HHMMSS}_{标题}/`；已存在时换用新时间戳，不覆盖已有目录。建立子目录：`data/`、`script/`、`result/`、`temp/`、`doc/`。
3. **启动 experiment 子 Agent**，注入固定上下文块：

   ```
   ORIGINAL_COMMAND: ::work -experiment ...
   DATE: YYYY-MM-DD
   TIME: HH:MM:SS
   REPORT_DIR: workspace/workreport_..._{标题}/
   CUSTOM_PROMPT: <用户自定义提示原文>
   TARGETS: [{type: file|dir, path: ...} 列表，可为空]
   启动指令：Read system/worker/templates/experiment.md 并按「Experiment 子 Agent 协议」执行
   ```

4. **主 Agent 独立验收**（不直接采信子 Agent 汇报）：子 Agent 返回后逐项核实——
   - 目录结构齐全（`data/`、`script/`、`result/`、`temp/`、`doc/` 与独立报告文件均存在）；
   - 报告五章结构齐全（一、研究内容 / 二、研究方法 / 三、研究结果 / 四、讨论 / 五、附件）；
   - 报告引用的每个结果文件名在 `result/` 真实存在；附件章列举的 `data/` 与 `script/` 文件与实际一致；
   - 第三章「逐图逐表解释」小节齐全：本章出现的每张结果表与同类型图组各有独立的一段话解释，归组的图组已逐一点名组内全部文件名并说明归组依据，无遗漏的图或表；
   - 抽查结果图：有标题、有完整图例、坐标轴有标签与单位。
   验收不通过时：简单缺失由主 Agent 直接补齐或修复；复杂缺失重新派发一次子 Agent 并在 prompt 中注明返工原因。
5. **汇总输出**：向用户报告工作目录路径、报告路径、结果文件数量与结论摘要（取完成信号的 `conclusion`）。

**日志摘要**：`实验报告写入 {REPORT_DIR}/报告.md | 结果 {N} 个 | 脚本 {M} 个 | 数据 {K} 个 | 状态: {完成/部分完成}`

## Experiment 子 Agent 协议

> 主 Agent 启动 experiment 子 Agent 时，在 prompt 中注入固定上下文块，并指示其 Read 本文件、严格按本节执行。
> 工作目录为当前仓库根目录（`AGENTS.md` 所在目录）。

**角色**：实验 Agent 由主 Agent 通过 `::work -experiment` 命令启动，围绕 `CUSTOM_PROMPT` 的研究问题设计并执行实验或数据分析。全部产物落在 `REPORT_DIR` 工作目录内，最终产出固定五章结构的中文报告。

**核心原则**：实验设计忠实于研究问题；结果如实呈现——不成功或不符合预期的结果同样写入报告并分析原因；禁止编造数据、结果或图。

### 文件权限声明

**允许执行**
- shell 命令：运行 `REPORT_DIR/script/` 中的脚本、数据处理与绘图、环境探测（`python3 --version`、已装包查询等）

**允许读取**
- `TARGETS` 中注入的全部目标
- 仓库内与任务相关的源码、文档、数据文件
- 本文件（`system/worker/templates/experiment.md`，系 `system/` 禁读规则的明确例外，仅用于确认本协议）

**允许写入**（仅限 `REPORT_DIR` 内）

| 路径 | 内容 |
|---|---|
| `data/` | 原始数据（复制、下载或生成的输入数据） |
| `script/` | 分析与实验脚本 |
| `result/` | 运行结果（结果数据与结果图） |
| `temp/` | 运行过程中产生的中间文件 |
| `doc/` | 有必要保留的中间文档（如实验设计草案） |
| `报告.md` | 最终报告（`REPORT_DIR` 根下独立的一个 md 文件） |

**禁止**
- 修改 `REPORT_DIR` 之外的任何文件（仓库源码、文档、配置）；禁止 Git 写操作
- 读取 `local.md`；读取除本文件外的 `system/` 其他文件；访问仓库根目录之外的文件（`TARGETS` 注入的除外）
- 编造数据、结果或图；删除不符合预期的结果
- 改动 `data/` 中的原始数据（一切变换由 `script/` 中的脚本完成）

### Step 0 — 解析参数

从 prompt 中提取主 Agent 注入的字段：`ORIGINAL_COMMAND`、`DATE` / `TIME`、`REPORT_DIR`、`CUSTOM_PROMPT`、`TARGETS`。

### Step 1 — 实验设计

- 明确研究问题，设计实验方案：做哪些实验/数据分析、对比基线是什么、关键参数有哪些。只有数据分析或只有实验设计均可；两种都有或多个并列时全部列出。
- 方案复杂时先把设计草案写入 `{REPORT_DIR}/doc/`；简单任务可直接进入 Step 2。

### Step 2 — 数据准备

- 原始数据归置 `data/`：从 `TARGETS` 或仓库路径复制、由脚本生成或下载；逐文件记录来源（供报告附件章使用）。
- 原始数据落盘后不再改动。

### Step 3 — 编写脚本

- 脚本写入 `script/`，须可直接从该目录运行（如 `cd script && python3 analyze.py`）；脚本内以相对路径引用 `../data`、`../result`、`../temp`。
- 中间产物写入 `temp/`；最终结果数据与图写入 `result/`。
- 绘图规范：每张图有标题、完整图例、坐标轴标签与单位（单位符合科学规范）；图面文字（标题/坐标轴/图例）使用英文。

### Step 4 — 运行与迭代

- 运行脚本，失败则修复重跑；结果不符合预期时如实记录并分析原因，不得删改数据凑结论。
- 运行日志与大体积中间文件留在 `temp/`。

### Step 5 — 撰写最终报告

写入 `{REPORT_DIR}/报告.md`，固定五章结构（五个章名与顺序不得增删；第三章内含「逐图逐表解释」小节）：

```markdown
# {中文标题}

## 一、研究内容
{根据用户的 prompt 生成的一段总体文字，介绍本研究的目的}

## 二、研究方法
{一段总体文字：本研究设计了哪些实验/数据分析、对比基线是什么、结果中关键参数有哪些；
只有数据分析或只有实验设计时写实际存在的一项；每类有多个时逐个分述}

{随后逐项展开每个实验/数据分析的设计，每项一个多步流程：
1 数据输入（什么数据、来自哪里）→ 2 预处理（做了什么变换）→ 3 算法/方法（含可选参数取值）
→ 4 得到什么结果数据/分析图；每一步是一句完整的话或一段完整的话。
可直接比较的多个实验可放在同一个表格中对比，但文段描述仍须完整；
存在多种实验/数据分析流程时全部写出}

## 三、研究结果
{完整的一段或几段话：描述实验结果以及结果对实验目标的意义}

{结果表直接展示在本章中；结果图逐一指明 result/ 目录中的具体文件名}

### 逐图逐表解释
{对本章出现的全部结果图与结果表逐个解释：每张结果表、每个同类型图组各占一个 `#### {图表名}` 小节，
小节内用完整的一段话先说明该图或表的意义与解读方法，再逐项解释表格的每一行、图例中的每个参数、
标题中的每一项非常识性内容，最后说明该图或表的结果对实验目标的意义。
同类型的多张图（同一指标、同一绘图形式、仅参数取值不同）合并为一个 `####` 小节：
开头列出该组包含的全部文件名并用一句话说明归为一组的依据，共用一段解释，不逐图重复；
类型不同的图不得合并，各写各的一段话。
涉及任何缩写或简写英文概念时，先解释这个概念本身，再解释其含义}

## 四、讨论
{对实验结果的进一步说明、局限解释、对后续工作的建议，完整文段；
涉及缩写或简写英文概念同样先解释概念本身（第三章已解释过的概念不重复解释）}

## 五、附件
### 数据（data/）
{逐个文件介绍：内容、格式、来源}
### 脚本（script/）
{逐个脚本介绍：功能、如何运行（含运行命令）}
```

### Step 6 — 完成信号

```
[EXPERIMENT_DONE]
report_dir: {REPORT_DIR}
report_file: {REPORT_DIR}/报告.md
results: [{result/ 下文件清单}]
scripts: [{script/ 下文件清单}]
data: [{data/ 下文件清单}]
conclusion: {一句话结论}
status: {完成 / 部分完成（原因）}
[/EXPERIMENT_DONE]
```

然后**立即退出**，不得再调用任何工具。

### 停止条件

- `CUSTOM_PROMPT` 缺失 → 主 Agent 报错中止；
- 实验必需的数据无法获得且无法生成 → 在报告中如实说明，标记「部分完成」；
- 脚本反复失败无法修复 → 保留 `temp/` 中的失败记录，报告写明失败点与已排除的原因，标记「部分完成」；
- 需要 `REPORT_DIR` 之外的写入权限或新增依赖无法解决 → 在报告中列为待授权/待解决事项，不擅自行动。
