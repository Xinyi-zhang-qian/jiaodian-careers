# ::pr

> 命令索引见 `system/command_reference.md`。本文件为 `::pr` 的完整执行协议。

---

## `::pr <目标仓库> <目标分支> [标题与说明]`

GitHub Pull Request 命令，是执行 `gh pr create` 的唯一通道。以 `local.md`「远程配置」表中 `::pr` 行配置的远程仓库与分支为 head，向用户指定仓库的指定分支发起 Pull Request。不 push、不 pull、不合并、不运行测试。由主 Agent 直接执行，不启动子 Agent。

**仅限用户手动调用**：本命令只能在用户当前消息中显式输入 `::pr` 时执行。禁止任何自动化流程调用或触发——包括 `/goal` 全自动模式、开发 loop 的各阶段（`::init` / `::req` / `::design` / `::devplan` / `::dev` / `::mergelocal` / `::lint` / `::ci` / `::doc` / `::devlog`）、其他命令的内部步骤、后台任务、定时任务与 CI 流水线。除本命令外，任何命令与日常交互都不得执行 `gh pr create` 或以其他方式创建 Pull Request。自动流程中出现 `::pr` 时，主 Agent 必须拒绝执行并告知用户本命令只能手动调用。

**参数格式**（由主 Agent 使用 LLM 能力直接解析）：
- `<目标仓库>`：必填。`owner/repo` 形式，PR 的 base 所在仓库；可以是当前仓库本身（同仓库分支间 PR），也可以是其他仓库（跨仓库 PR）。
- `<目标分支>`：必填。PR 的 base 分支名。
- `[标题与说明]`：可选。缺省时由主 Agent 按下文「PR 信息模板与语言规范」生成标题与正文；已提供时按模板结构整理补全。

目标仓库或目标分支缺失、或用户表述无法确定唯一目标时，**停止执行**并告知用户需要明确指定「目标仓库（owner/repo）与目标分支」，不得自行推测默认值。

**前置条件**：
- `local.md` 的「GitHub 配置 → 远程配置」表中 `::pr` 行的远程仓库与远程分支已填写（由 `/init` 建库时用户指定，不预设 `master`）；未填写时停止，向用户询问并写入后再继续；
- `local.md` 的目标仓库远程地址与凭据可用，`gh auth status` 认证正常；
- 主工作区无未提交变更（`git status --porcelain` 输出为空）；有未提交变更时停止，提示用户先提交（本命令不代为提交）；
- head 与 base 相同（目标仓库与 `::pr` 行的远程仓库相同、且目标分支与 `::pr` 行的远程分支同名）时停止，告知用户同一分支无需提 PR。

**执行步骤（主 Agent 逐步执行，不得跳步）**

**步骤 1 — checkout head 分支**：读取 `local.md`「远程配置」表中 `::pr` 行的 `{head仓库}` 与 `{head分支}`；解析远程名：在 `git remote -v` 中找到指向 `{head仓库}` 的远程名（通常为 `origin`）记为 `{远程}`，找不到时**停止流程**，提示用户先用 `git remote add` 添加指向 `{head仓库}` 的远程后重试。随后执行：

```bash
git fetch {远程} {head分支}
git checkout {head分支}          # 本地无同名分支时改用：git checkout -b {head分支} --track {远程}/{head分支}
```

只做切换，不 reset、不改写本地分支历史；fetch 失败（认证、网络、无读取权限）时停止并原样报告错误。

**步骤 2 — 判定本地与远程的关系**：记 `LOCAL=$(git rev-parse HEAD)`、`REMOTE=$(git rev-parse {远程}/{head分支})`，按以下关系处理：

| 关系 | 判定方法 | 处置 |
| --- | --- | --- |
| 一致 | `LOCAL == REMOTE` | 进入步骤 3 |
| 本地严格包含远程 HEAD，或双方分叉 | `git merge-base --is-ancestor {REMOTE} {LOCAL}` 成功且两者不等，或两边互不为祖先 | **停止流程**，告知用户本地有未 push 的内容，需先执行 `::push`（分叉时先手动 merge）把本地内容推送到 head 分支后再提 PR |
| 远程严格包含本地 HEAD | `git merge-base --is-ancestor {LOCAL} {REMOTE}` 成功且两者不等 | 继续进入步骤 3，并向用户提示本地落后于远程分支（PR 的 head 是远程分支，本地落后不影响 PR 内容；建议择时 `::pull`） |

**步骤 3 — 权限与既有 PR 探测**：

1. 目标仓库权限：`gh repo view {目标仓库} --json viewerPermission`；
   - 仓库不可见（404、认证失败）→ **停止流程**，原样报告错误；
   - `viewerPermission` 不是 `ADMIN` / `MAINTAIN` / `WRITE` → **停止流程**，告知用户没有向 `{目标仓库}` 提 PR 的权限；本命令不自动 fork，需要 fork 流程时由用户手动处理；
2. 既有开放 PR：从 `{head仓库}`（owner/repo 形式）解析所有者部分为 `{head所有者}`，执行 `gh pr list --repo {目标仓库} --head {head所有者}:{head分支} --state open --json url`；已存在开放 PR → **停止流程**，报告既有 PR 的链接，告知用户同一 head 分支已有进行中的 PR。

**步骤 4 — 生成 PR 信息并创建**：按下文「PR 信息模板与语言规范」生成标题与正文（用户已在参数中给出标题与说明时，按模板结构整理补全），执行：

```bash
gh pr create --repo {目标仓库} --base {目标分支} --head {head所有者}:{head分支} --title {标题} --body {正文}
```

- base 分支不存在、权限不足、无提交差异（head 与 base 内容一致）等失败情形 → **停止流程**并原样报告错误输出；
- 成功 → 向用户报告 PR 的 URL 与「head → base」（`{head仓库}:{head分支}` → `{目标仓库}:{目标分支}`）。

**步骤 5 — 收尾**：向用户输出摘要（checkout 结果、关系判定、权限探测、PR 链接或停止原因）；按本文件末尾模板追加 `system_log.md`，并按 `system/command_reference.md`「全局：本地提交规范」在本地提交这次日志变更。注意：日志提交会使本地重新领先远程分支一个提交，属预期行为——下一次 `::pr` 会因此命中「本地有未 push 的内容」而停止，需先 `::push`。

## PR 信息模板与语言规范

PR 的标题与正文由主 Agent 生成。正文默认使用以下模板，四节标题与注释保持原文不变；用户已在参数中给出标题与说明时，按此结构整理补全，不省略任何一节：

```markdown
### 做了什么 (What)
<!-- 简述本次改动的内容 -->

### 为什么做 (Why)
<!-- 简述背景、原因或关联的 Issue/工单号 (如: Fixes #123) -->

### 怎么测的 (How Tested)
<!-- 简述验证方式、测试结果或截图 -->

### 自查项 (Checklist)
- [ ] 本地测试通过
- [ ] 已处理边界情况与异常
- [ ] 如有配置/数据库变更，已在下方备注上线注意事项
```

填写规则：

- 「做了什么」：按 head 相对 base 的提交清单与变更摘要总结（`git log` 与 `git diff --stat`；base 分支在本地无对应引用时，以本轮 loop 的提交与 `status.md` / `system/devlog/` 记录为据）。
- 「为什么做」：从需求文档（`docs/requirements.md`）或用户的 prompt（本轮 `::init` 的 custom prompt、用户原始要求原文）总结背景与原因；两者都不可得时如实写明「未找到需求来源，待补充」，禁止编造动机。关联 Issue 或工单号按用户给定的编号填写（如 `Fixes #123`），用户未提及时不虚构编号。
- 「怎么测的」：从 `docs/test.md` 的「最近一轮结果」与相关提交总结验证方式与结果；fast 轮次只有模块级测试时如实写明验证范围。
- 「自查项」：按实际情况勾选；未落实的项保持未勾选，不得虚勾。
- PR 标题与正文必须使用中文，并**强制遵守** `AGENTS.md`「全局语言规范」的全部规则（完整成分句、避免黑话空话、术语首次出现就地解释、不堆砌抽象名词等）。

**规则**：
- 本命令是唯一允许创建 Pull Request 的通道，且只能由用户手动调用；任何流水线、循环或自动化都不得触发（见开头「仅限用户手动调用」）。
- 三个停止条件任一命中即停止并告知用户：目标（仓库或分支）未明确指定；无 PR 权限（目标仓库不可见或无写权限）；本地有未 push 的内容（本地领先远程或双方分叉）。
- PR 标题与正文默认按「PR 信息模板与语言规范」生成，「为什么做」一节的信息源为需求文档或用户 prompt，语言风格强制遵守 `AGENTS.md` 全局语言规范。
- 本命令不 push、不 pull、不合并、不运行测试、不自动 fork、禁止 `--force` 类操作；远程分支与 base 的差异内容原样进入 PR，不做任何改写。
- 本命令不在开发 loop 的阶段链中，其他命令不得在内部调用；用户可随时手动调用。

## 运行日志

本命令执行完毕后，必须向仓库根目录 `system_log.md` 追加一条记录：

````markdown
## [YYYY-MM-DD HH:MM:SS] {命令原文}
- 远程分支: {远程分支} | 目标: {owner/repo}:{目标分支} | 关系: {一致/远程严格包含本地/本地有未推送提交（已停止）} | PR: {已创建 {PR URL} / 已停止（原因）}
````
