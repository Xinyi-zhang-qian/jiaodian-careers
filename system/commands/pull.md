# ::pull

> 命令索引见 `system/command_reference.md`。本文件为 `::pull` 的完整执行协议。

---

## `::pull`

GitHub 远程拉取命令。只做快进拉取：仅当远程分支严格包含本地 HEAD 时把远程提交拉取到本地；不自动 merge、不自动 rebase。由主 Agent 直接执行，不启动子 Agent。

**参数格式**：无参数。

**前置条件**：
- `local.md` 的「GitHub 配置 → 远程配置」表中 `::pull` 行的远程仓库与远程分支已填写（由 `/init` 建库时用户指定，不预设 `master`）；未填写时停止，向用户询问并写入后再继续；
- `local.md` 的目标仓库远程地址与凭据可用；
- 主工作区无未提交变更（`git status --porcelain` 输出为空）；有未提交变更时停止，提示用户先提交（拉取会改变工作区，本命令不代提交）。

**执行步骤（主 Agent 逐步执行，不得跳步）**

**步骤 1 — checkout 远程分支**：读取 `local.md`「远程配置」表中 `::pull` 行的 `{远程仓库}` 与 `{远程分支}`；解析远程名：在 `git remote -v` 中找到指向 `{远程仓库}` 的远程名（通常为 `origin`）记为 `{远程}`，找不到时**停止流程**，提示用户先用 `git remote add` 添加指向 `{远程仓库}` 的远程后重试。随后执行：

```bash
git fetch {远程} {远程分支}
git checkout {远程分支}          # 本地无同名分支时改用：git checkout -b {远程分支} --track {远程}/{远程分支}
```

只做切换，不 reset、不改写本地分支历史；fetch 失败（认证、网络、无读取权限）时停止并原样报告错误。

**步骤 2 — 判定远程与本地的关系**：记 `LOCAL=$(git rev-parse HEAD)`、`REMOTE=$(git rev-parse {远程}/{远程分支})`，按以下关系处理：

| 关系 | 判定方法 | 处置 |
| --- | --- | --- |
| 一致 | `LOCAL == REMOTE` | 无变更可拉取，报告后结束 |
| 远程严格包含本地 HEAD | `git merge-base --is-ancestor {LOCAL} {REMOTE}` 成功且两者不等 | 进入步骤 3 快进拉取 |
| 其他情况（本地严格包含远程 HEAD，或双方分叉） | 上述判定不成立 | **停止流程**，告知用户远程分支未严格包含本地 HEAD，需要用户手动 merge 后再拉取；本命令不自动 merge、不自动 rebase |

**步骤 3 — 快进拉取**：执行 `git merge --ff-only {远程}/{远程分支}`（等价于只允许快进）。
- 成功 → 报告拉取范围（`{本地旧 HEAD 前 12 位}..{远程 HEAD 前 12 位}`）；
- 失败 → **停止流程**并报告错误，不得改用普通 `git merge` 或 `git rebase` 兜底。

**步骤 4 — 收尾**：向用户输出摘要（checkout 结果、关系判定、拉取范围或停止原因）；按本文件末尾模板追加 `system_log.md`，并按 `system/command_reference.md`「全局：本地提交规范」在本地提交这次日志变更。

**规则**：
- 只允许快进拉取；远程分支未严格包含本地 HEAD 时一律停止并交由用户手动 merge（含本地领先与双方分叉两种情形），不得自动合并或变基。
- 本命令不在开发 loop 的阶段链中，其他命令不得在内部调用；用户可随时手动调用。
- 本命令不修改代码（只接受远程已有的提交），不运行测试、不推送。

## 运行日志

本命令执行完毕后，必须向仓库根目录 `system_log.md` 追加一条记录：

````markdown
## [YYYY-MM-DD HH:MM:SS] {命令原文}
- 远程分支: {远程分支} | 关系: {一致/远程严格包含本地/其他（本地领先或分叉，已停止）} | 拉取: {已快进 {旧前12位}..{新前12位} / 无变更 / 已停止（原因）}
````
