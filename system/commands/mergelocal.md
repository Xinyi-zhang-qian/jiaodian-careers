# ::mergelocal

> 命令索引见 `system/command_reference.md`。本文件为 `::mergelocal` 的完整执行协议。

---

## `::mergelocal`

分支合并命令。开发 loop 的「分支合并」阶段（`::dev` 之后、`::lint` 之前；fast loop 中位于 `::devlog` 之前）：把 `::dev` 为各模块开立的本地分支（`dev/*`）全部合并回主工作区当前分支，自动处理合并冲突；全部合并完成后清理全部本地 worktree，只保留主工作区一个。由主 Agent 直接执行（合并裁决需要全局视角，不启动子 Agent）。

**参数格式**：无参数。

**前置条件**：`local.md` 的「::dev Worktree 清单」非空，或存在未合并的 `dev/*` 本地分支；二者皆无时报「无待合并分支」并直接进入步骤 6 的状态推进（本阶段无事可做）。

**手动调用检查（门禁）**：本命令由用户手动调用时，先执行 `system/command_reference.md` 的「阶段门禁与手动调用提醒」：读 `status.md` 的 `[Current Phase]` 与 `[Phase History]`，向用户报告上一阶段（模块开发）的完成情况——checklist 各模块是否均已完成、`local.md` 清单中各 worktree 状态；模块开发未完成时提醒用户先执行 `::dev`（全自动情景除外）。

**执行步骤（主 Agent 逐步执行，不得跳步）**

**步骤 1 — 核对合并对象**：读取 `local.md` 的「::dev Worktree 清单」、`git worktree list` 与 `git branch --list 'dev/*'` 三方状态；不一致时以 git 实际状态为准修正 `local.md` 清单并向用户报告偏差。确定待合并分支清单。

**步骤 2 — 确认主工作区洁净**：`git status --porcelain` 应为空（`::dev` 收尾提交已完成）；有未提交变更时先按「全局：本地提交规范」提交或向用户报告处理。主工作区当前分支即集成分支。

**步骤 3 — 逐个合并分支**：对待合并清单中的每个分支执行 `git merge --no-ff dev/{模块名}`（按清单登记顺序逐个合并，合并提交信息用中文，注明并入的模块）。

**步骤 4 — 冲突自动处理**：合并出现冲突时逐文件裁决，默认自动处理、不中断流程：

1. **文档类冲突**（`docs/test.md`、`docs/modules/`、`docs/` 全局文档、`plans/` 等）：原则上取双方并集——两条登记条目、两段文档变更都保留，同一小节内去重并按模块归位；语义级冲突（同一接口两种写法）按交互文档与已合并代码的真实行为裁决；
2. **代码类冲突**：按模块职责边界裁决——各模块自有文件的冲突以该模块分支的版本为准，共享文件的冲突按 `docs/interaction.md` 与模块交互文档的规格裁决；裁决后必须运行受影响模块的模块测试验证通过（只跑受影响模块的测试，全量回归留待 `::ci`）；
3. 仅当两种改动在语义上互斥、且依据文档规格与测试均无法裁决时，才停下向用户报告冲突双方原文并请示；全自动情景下按最符合需求文档与交互文档的方案裁决，并在日志中记录裁决理由；
4. 每处冲突的裁决依据（取哪方、为什么）记录进该次合并提交的信息体。

**步骤 5 — 清理 worktree 与分支**：全部分支合并完成且工作区洁净后：

1. 对每个登记的 worktree 执行 `git worktree remove .worktrees/{模块名}`（remove 失败且确认该 worktree 无未提交变更时使用 `--force`；有未提交变更时先核对内容是否已并入集成分支，未并入时停下报告）；
2. 删除已合并的本地分支 `git branch -d dev/{模块名}`；
3. 清空 `local.md` 的「::dev Worktree 清单」为 `（无）`；
4. `git worktree list` 确认只剩主工作区一个 worktree。

**步骤 6 — 状态推进**：更新 `status.md`：向 `[Phase History]` 本轮行追加 `分支合并（{YYYY-MM-DD HH:MM}）`；标准 loop 将 `[Current Phase]` 置为 `代码检查` 并提示执行 `::lint`；fast loop（`[Fast Baseline]` 非空）将 `[Current Phase]` 置为 `开发日志` 并提示执行 `::devlog`。

**规则**：
- 合并全部完成前禁止清理任何 worktree 与分支；清理与合并不得交叉进行。
- 冲突裁决只运行受影响模块的模块测试，不得在本命令中执行全量回归（归 `::ci`）。
- 本命令自身不改业务逻辑：裁决只解决「两个分支如何并存」，不引入合并内容之外的新改动。
- 本命令只处理本地 `dev/*` 分支的合并；远程分支的拉取与推送分别由 `::pull` 与 `::push` 负责，二者不做自动合并，需要合并远程内容时由用户手动处理。

## 运行日志

本命令执行完毕后，必须向仓库根目录 `system_log.md` 追加一条记录，并按 `system/command_reference.md`「全局：本地提交规范」完成本地提交（合并提交与本命令的状态、清单、日志变更一并计入）。

````markdown
## [YYYY-MM-DD HH:MM:SS] {命令原文}
- 合并分支: [dev/{模块名}×N] | 冲突: {N} 处（自动裁决 {N} / 请示用户 {M}） | worktree 清理: {N} 个（剩余 1） | 进入阶段: {代码检查/开发日志}
````
