# ::push

> 命令索引见 `system/command_reference.md`。本文件为 `::push` 的完整执行协议。

---

## `::push`

GitHub 远程推送命令，是执行 `git push` 的唯一通道。只做快进推送：不 pull、不合并、不运行测试。由主 Agent 直接执行，不启动子 Agent。

**仅限用户手动调用**：本命令只能在用户当前消息中显式输入 `::push` 时执行。禁止任何自动化流程调用或触发——包括 `/goal` 全自动模式、开发 loop 的各阶段（`::init` / `::req` / `::design` / `::devplan` / `::dev` / `::mergelocal` / `::lint` / `::ci` / `::doc` / `::devlog`）、其他命令的内部步骤、后台任务、定时任务与 CI 流水线。除本命令外，任何命令与日常交互都不得执行 `git push`；创建 Pull Request（`gh pr create`）由 `::pr` 命令独占（协议见 `system/commands/pr.md`）。自动流程中出现 `::push` 时，主 Agent 必须拒绝执行并告知用户本命令只能手动调用。

**参数格式**：无参数。

**前置条件**：
- `local.md` 的「GitHub 配置 → 远程配置」表中 `::push` 行的远程仓库与远程分支已填写（由 `/init` 建库时用户指定，不预设 `master`）；未填写时停止，向用户询问并写入后再继续；
- `local.md` 的目标仓库远程地址与凭据可用；
- 主工作区无未提交变更（`git status --porcelain` 输出为空）；有未提交变更时停止，提示用户先提交（本命令不代为提交，避免推送未经确认的内容）；
- **devlog 欠账门控**：`status.md` 存在且含 `[Devlog Backlog]` 字段时，其内容必须为 `（无）`（空清单）；存在未追赶的 fast 开发记录时**停止流程**，向用户报告欠账条数与各条目，告知用户 fast 开发的全局文档欠账未补齐前不得推送到远程，须先执行 `::doc` 追赶清空清单后再推送。`status.md` 不存在或无 `[Devlog Backlog]` 字段时视为无欠账，不阻塞。

**执行步骤（主 Agent 逐步执行，不得跳步）**

**步骤 1 — checkout 远程分支**：读取 `local.md`「远程配置」表中 `::push` 行的 `{远程仓库}` 与 `{远程分支}`；解析远程名：在 `git remote -v` 中找到指向 `{远程仓库}` 的远程名（通常为 `origin`）记为 `{远程}`，找不到时**停止流程**，提示用户先用 `git remote add` 添加指向 `{远程仓库}` 的远程后重试。随后执行：

```bash
git fetch {远程} {远程分支}
git checkout {远程分支}          # 本地无同名分支时改用：git checkout -b {远程分支} --track {远程}/{远程分支}
```

只做切换，不 reset、不改写本地分支历史；fetch 失败（认证、网络、无读取权限）时停止并原样报告错误。

**步骤 2 — 判定本地与远程的关系**：记 `LOCAL=$(git rev-parse HEAD)`、`REMOTE=$(git rev-parse {远程}/{远程分支})`，按三态处理：

| 关系 | 判定方法 | 处置 |
| --- | --- | --- |
| 一致 | `LOCAL == REMOTE` | 无变更可推送，报告后结束（不执行 push） |
| 本地严格包含远程 HEAD | `git merge-base --is-ancestor {REMOTE} {LOCAL}` 成功且两者不等 | 进入步骤 3 推送 |
| 远程严格包含本地 HEAD，或双方分叉 | 上述判定不成立 | **停止流程**，告知用户远程分支存在本地没有的提交，需用户手动 merge 后再推送；本命令不自动 pull、不自动 merge |

**步骤 3 — 权限探测与推送**：

1. 先做只读探测：`git push --dry-run {远程} HEAD:{远程分支}`；
   - 认证失败或无写权限（`Permission denied`、`403`、`Write access to repository not granted` 等）→ **停止流程**，告知用户检查 `local.md` 的 PAT 与目标仓库写权限；
   - 非快进被拒（远程在 fetch 后又有新提交）→ **停止流程**，告知用户需手动 merge；
   - 其他错误 → 停止并原样报告错误输出；
2. 探测通过后执行 `git push {远程} HEAD:{远程分支}`，报告推送范围（`{远程旧 HEAD 前 12 位}..{本地 HEAD 前 12 位}`）。

**步骤 4 — 收尾**：向用户输出摘要（checkout 结果、关系判定、推送范围或停止原因）；按本文件末尾模板追加 `system_log.md`，并按 `system/command_reference.md`「全局：本地提交规范」在本地提交这次日志变更。

**规则**：
- 本命令是唯一允许执行 `git push` 的通道，且只能由用户手动调用；任何流水线、循环或自动化都不得触发（见开头「仅限用户手动调用」）。
- 推送前必须同时满足「`[Devlog Backlog]` 无欠账」「本地严格包含远程 HEAD」与「dry-run 权限探测通过」；任一不满足即停止，不得重试强推（禁止 `--force`）。
- 本命令不修改代码、不运行测试、不合并分支；远程有本地没有的提交时一律交给用户手动 merge。

## 运行日志

本命令执行完毕后，必须向仓库根目录 `system_log.md` 追加一条记录：

````markdown
## [YYYY-MM-DD HH:MM:SS] {命令原文}
- 远程分支: {远程分支} | 关系: {一致/本地严格包含远程/远程含本地缺失提交} | 推送: {已推送 {旧前12位}..{新前12位} / 无变更 / 已停止（原因）}
````
